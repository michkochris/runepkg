Runepkg Personal Direction, Unshielding & Absolute Tooling Independence Implementation Ledger
This implementation plan serves as the definitive architectural ledger and roadmap for runepkg. It captures your personal vision—combining Debian package structures and archive conventions as raw material with Cross Linux From Scratch (CLFS) cross-building discipline and the robust, minimal rescue spirit of Damn Small Linux (DSL)—while documenting all unshielding modifications and absolute tooling independence extensions.
1. Intentions & Architectural Vision
•
Debian Structure Without Binary Dogma: Utilizing Debian .dsc source packages and .deb archives purely as raw material and supply chain building blocks, rather than abiding by host distro binary constraints.
•
CLFS & DSL Rescue Mindset: Establishing clean, independent execution paths for tools on your terms, capable of rescuing and bringing up minimal Linux environments from scratch.
•
Absolute Tooling Independence & Unshielding: Transitioning runepkg from a defensive host-protected manager into an unhindered, direct-mutation deployment engine that resolves full dependency trees (libc6, libgcc-s1, libmagic, etc.) and installs payloads directly without artificial host restrictions.
2. Breadcrumbs: Core Subsystems
The Psychic Subsystem (runepkg_psychic.c / .h)
•
Purpose: Pre-flight prophecy checks, target architecture detection, and dynamic linker discovery.
•
Key Extension: runepkg_psychic_verify_and_anchor_linker() which scans sysroots post-extraction to locate where the dynamic linker (ld-linux-x86-64.so.2) landed (lib/ vs usr/lib/) and atomically re-anchors /lib/ and /lib64/ loader symlinks so they are never broken or dangling.
The Antimatter Subsystem (runepkg_antimatter.c / .h)
•
Purpose: Payload validation, boundary assertions, and transaction safety.
•
Unshielding Modification: runepkg_antimatter_shield_check() was decoupled and made to return RUNEPKG_DECON_OK unconditionally, removing live-root core glibc mutation blocks.
The Matryoshka Deployment Engine (main_matryoshka_plan.txt)
•
Purpose: Russian nesting doll architecture for isolated, nested sysroots and container deployments under /mnt/runepkg/ and /srv/lib/runepkg_dir/install_dir.
3. Summary of Changes Made to Remove Defensive Restrictions
1.
runepkg_antimatter.c (Matryoshka Shield Unshielding):
◦
Bypassed core glibc live-root mutation refusal, allowing direct mutation of / when desired.
2.
runepkg_install.c (Wrapper & Defensive Unshielding):
◦
Decoupled runepkg_install_generate_tooling_wrappers() (set aside for future alternate-root isolation).
◦
Set aside payload validation restrictions.
3.
runepkg_defensive.c (Host Infrastructure Check Unshielding):
◦
Modified runepkg_defensive_check_critical_host_package() to return RUNEPKG_SUCCESS unconditionally, eliminating defensive refusals when installing core system packages like libc6 directly onto live host /.
4.
runepkg_resolver.cpp (Uniform Dependency Resolution):
◦
Decoupled host_installed_map pruning during MODE_INSTALL. runepkg now resolves and pulls in the full minimal pruned dependency tree (libc6, libgcc-s1, libmagic, etc.) uniformly across the board instead of pruning dependencies already present on the host OS.
