Extract Pre-Depends & Depends: Treat Pre-Depends as hard immediate barriers (must be completely configured before unpacking the dependent package).

Topological Sort (Kahn's Algorithm / Tarjan's SCC):

For pure DAGs: Order packages so that if B depends on A, A appears before B.

For cyclic dependencies (common in Debian base/core packages): Break cycles by batching the cyclic cluster into a single multi-package dpkg --unpack step.

Debian's modern standard relies strictly on Merged-/usr (enforced via usrmerge / base-files), multiarch library tuple paths, and isolated local/third-party prefixes.



If you are constructing a toolchain/sysroot or sandbox prefix for building Debian-compatible packages, here is the canonical layout and initialization script.



Debian Modern FHS Structure Overview

Merged-/usr: Root binaries and libraries are symlinks into /usr (/bin → usr/bin, /sbin → usr/sbin, /lib → usr/lib, /lib64 → usr/lib64).



Multiarch Triplet Hierarchy: Debian separates target architectures into /usr/lib/<triplet> and /usr/include/<triplet> (e.g., x86_64-linux-gnu, aarch64-linux-gnu).



Package/Toolchain Prefix Hierarchy:



System tools / packaging targets: /usr



Local host-built overrides: /usr/local



Isolated third-party tools: /opt



Package manager variable state: /var/lib/<pkg-manager-name> and /var/cache/<pkg-manager-name>



Sysroot & Prefix Initialization Script

This POSIX shell script initializes a clean, Debian-compliant directory skeleton with merged /usr and proper multiarch targets under a custom install prefix (or sysroot path).



Bash

#!/usr/bin/env sh

set -eu



# Target sysroot or install prefix

PREFIX="${1:-./debian_sysroot}"

TARGET_TRIPLET="${2:-$(gcc -dumpmachine 2>/dev/null || echo "x86_64-linux-gnu")}"



echo "Initializing Debian FHS at: ${PREFIX}"

echo "Configuring multiarch triplet: ${TARGET_TRIPLET}"



# 1. Create canonical /usr tree

mkdir -p "${PREFIX}/usr/bin" \

"${PREFIX}/usr/sbin" \

"${PREFIX}/usr/include/${TARGET_TRIPLET}" \

"${PREFIX}/usr/lib/${TARGET_TRIPLET}" \

"${PREFIX}/usr/share/man" \

"${PREFIX}/usr/share/doc" \

"${PREFIX}/usr/local/bin" \

"${PREFIX}/usr/local/lib" \

"${PREFIX}/usr/local/include"



# 2. Setup 64-bit symlink if multiarch is 64-bit

if [ "${TARGET_TRIPLET%%-*}" = "x86_64" ] || [ "${TARGET_TRIPLET%%-*}" = "aarch64" ]; then

mkdir -p "${PREFIX}/usr/lib64"

ln -sfn "usr/lib64" "${PREFIX}/lib64"

fi



# 3. Create Root Merged-/usr Symlinks (relative links avoid chroot breaks)

ln -sfn usr/bin "${PREFIX}/bin"

ln -sfn usr/sbin "${PREFIX}/sbin"

ln -sfn usr/lib "${PREFIX}/lib"



# 4. Standard runtime and system dirs

mkdir -p "${PREFIX}/etc" \

"${PREFIX}/dev" \

"${PREFIX}/proc" \

"${PREFIX}/sys" \

"${PREFIX}/tmp" \

"${PREFIX}/run" \

"${PREFIX}/var/log" \

"${PREFIX}/var/run" \

"${PREFIX}/var/lib/dpkg" \

"${PREFIX}/var/cache/apt/archives/partial" \

"${PREFIX}/opt"



# Maintain /var/run -> /run symlink

ln -sfn ../run "${PREFIX}/var/run"



chmod 1777 "${PREFIX}/tmp"



echo "Debian FHS skeleton created successfully."

Key Considerations for C/C++ Debian Package Managers

Relative Symlinks: Always use relative links (e.g., ln -s usr/bin "${PREFIX}/bin") rather than absolute paths so the sysroot remains fully functional outside of a chroot.



Multiarch Triplet Paths: When setting up your C/C++ compiler driver wrappers, ensure default search paths include:



Headers: -isystem ${PREFIX}/usr/include/${TARGET_TRIPLET} -isystem ${PREFIX}/usr/include



Libraries: -L${PREFIX}/usr/lib/${TARGET_TRIPLET} -L${PREFIX}/usr/lib



Dynamic Linker (ld.so): On Debian x86_64, the dynamic linker hardcodes /lib64/ld-linux-x86-64.so.2 (pointing to usr/lib/x86_64-linux-gnu/ld-linux-x86-64.so.2). Keeping /lib64 as a symlink ensures statically and dynamically linked Debian ELF binaries execute cleanly.

Targeting standard Debian compatibility directly inside the .deb payloads makes your cross-compiled packages native to Debian/Kali systems, multiarch environments, and embedded rootfs targets without relying on custom wrapper hacks or non-standard paths.

1. The Dynamic Linker (PT_INTERP) Prediction Model
Debian decouples where the dynamic linker physically lives from what is hardcoded in ELF headers.

On Debian/GNU/Linux systems, the physical dynamic linker lives in the multiarch path (/usr/lib/<triplet>/ld-*.so), but the ELF program interpreter header (PT_INTERP) points to a well-known legacy path in root /lib or /lib64 via symlinks.

Debian Canonical Interpreter Map:
Target Profile Triplet	Physical Location in Debian	Hardcoded PT_INTERP Path
x86_64-linux-gnu	/usr/lib/x86_64-linux-gnu/ld-linux-x86-64.so.2	/lib64/ld-linux-x86-64.so.2
i386-linux-gnu	/usr/lib/i386-linux-gnu/ld-linux.so.2	/lib/ld-linux.so.2
aarch64-linux-gnu	/usr/lib/aarch64-linux-gnu/ld-linux-aarch64.so.1	/lib/ld-linux-aarch64.so.1
arm-linux-gnueabihf	/usr/lib/arm-linux-gnueabihf/ld-linux-armhf.so.3	/lib/ld-linux-armhf.so.3
x86_64-linux-musl	/usr/lib/x86_64-linux-musl/libc.so	/lib/ld-musl-x86_64.so.1
x86_64-musl-static	None (Static)	None (Zero Header)
How runepkg Predicts & Sets target-profile-ld:
For Dynamic Targets (*-gnu, *-musl): Inject --dynamic-linker=<standard_pt_interp> into target LDFLAGS. This guarantees that if the .deb is extracted or installed on any Debian-derived system, the kernel finds the interpreter immediately without wrapper scripts.

For Static Targets (*-static): Pass -static to enforce zero dynamic dependencies and strip PT_INTERP entirely.

2. Standard Debian Payload Packaging Architecture
Inside each generated {target-pkg}.deb (data.tar.xz), structure the payload with pure Debian FHS and multiarch layout:

{target-pkg}.deb / data.tar.xz
├── usr/
│   ├── bin/                        # Host/Target executable binaries
│   ├── sbin/                       # System administration binaries
│   ├── lib/
│   │   └── x86_64-linux-gnu/       # Architecture-dependent shared objects (.so.*)
│   │       ├── libfoo.so.1 -> libfoo.so.1.0.0
│   │       └── libfoo.so.1.0.0
│   └── share/
│       ├── doc/<pkgname>/          # Debian changelog, copyright, docs
│       └── man/                    # Manpages
└── etc/
    └── ld.so.conf.d/               # Optional dynamic linker config
        └── <target-triplet>-runepkg.conf
Note on Merged-/usr in .deb archives:
In Debian package construction (via dpkg-deb), package payloads should not contain root-level directory symlinks like bin -> usr/bin inside the package archive itself. Debian delegates the creation of root symlinks to the base system packages (base-files / usrmerge). Shipping /bin or /lib symlinks directly in individual third-party .deb archives can cause dpkg unpack conflicts (overwriting directory with symlink). Pack files into usr/bin, usr/sbin, and usr/lib/<triplet>.

3. Header & Multiarch Metadata Integration
To make Debian's native tools (dpkg, apt, pkg-config) aware of your target package, include Debian's multiarch control headers in the control.tar.xz file of the .deb:

Ini, TOML
Package: libfoo
Version: 1.0.0
Architecture: amd64
Maintainer: runepkg
Section: libs
Priority: optional
Multi-Arch: same
Depends: libc6 (>= 2.34)
Description: Clean cross-compiled library with minimal runtime dependencies
Multi-Arch: same: Enables co-installing this package alongside foreign-architecture packages (e.g., libfoo:amd64 and libfoo:arm64 simultaneously on the same system).

Multi-Arch: foreign: Use for architecture-independent utilities or binaries that provide the exact same CLI behavior regardless of architecture (e.g., build tools, code generators).

4. Implementation Logic for runepkg
C++
// In runepkg_bootstrap.cpp / debian_builder module:

struct TargetProfileSpec {
    std::string profile_name;        // e.g. "x86_64-linux-gnu"
    std::string deb_arch;            // "amd64"
    std::string triplet;             // "x86_64-linux-gnu"
    std::string pt_interp;           // "/lib64/ld-linux-x86-64.so.2"
    bool is_static;                  // false
};

TargetProfileSpec get_profile_spec(const std::string& profile) {
    if (profile == "x86_64-musl-static") {
        return {"x86_64-musl-static", "amd64", "x86_64-linux-musl", "", true};
    }
    if (profile == "x86_64-linux-gnu") {
        return {"x86_64-linux-gnu", "amd64", "x86_64-linux-gnu", "/lib64/ld-linux-x86-64.so.2", false};
    }
    if (profile == "aarch64-linux-gnu") {
        return {"aarch64-linux-gnu", "arm64", "aarch64-linux-gnu", "/lib/ld-linux-aarch64.so.1", false};
    }
    // Fallback or custom profiles...
    return {};
}

void apply_target_linker_flags(const TargetProfileSpec& spec, BuildEnv& env) {
    if (spec.is_static) {
        env.ldflags += " -static";
    } else {
        env.ldflags += " -Wl,--dynamic-linker=" + spec.pt_interp;
        env.ldflags += " -Wl,-rpath-link=/usr/lib/" + spec.triplet;
    }
}
This ensures target .deb binaries execute cleanly whether run from a standard Debian rootfs, booted on an embedded board, or managed inside a minimal container.
