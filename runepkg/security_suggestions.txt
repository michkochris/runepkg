1. Unsafe strdup() Usage in Cryptography Module ⚠️
Location: runepkg_crypto.c, lines 21–28

C
static char* get_pkg_name_from_path(const char* file_path) {
    char* bname = strdup(file_path);
    char* base = basename(bname);
    char* underscore = strchr(base, '_');
    char* result;
    if (underscore) *underscore = '\0';
    result = strdup(base);
    free(bname);
    return result;
}
Issues:

Uses non-portable strdup() instead of the secure runepkg_secure_strdup() wrapper
No NULL pointer check after strdup() calls
basename() is not thread-safe on all platforms and can modify its input
Memory is allocated but callers may not free it (line 66: free(pkg_name) is only called in success path)
Recommendation: Replace with runepkg_secure_strdup() and validate all allocations.

Issues:

Executes arbitrary scripts from .deb packages without sandboxing
Only checks if installing to root (/), but doesn't validate script content, permissions, or source
No capability dropping or privilege limitation before execution
Malicious package maintainers can execute any command with installation privileges
No audit logging of what scripts execute or with what arguments
Recommendation:

Verify script signatures before execution
Drop unnecessary privileges before running scripts
Use seccomp/AppArmor to sandbox script execution
Log all script executions with full arguments
