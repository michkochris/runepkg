1. py3compile Postinst Failures ⚠️ RUNEPKG BUG
Pattern: Multiple Python packages fail with:

Code
Exception: cannot get content of <package-name>
Root cause: The py3compile script tries to query the package database using dpkg, but when runepkg installs a package, it may not immediately update dpkg's index in a way that py3compile can read.

Affected packages:

nemo-data, python3-pampy, python3-ptyprocess, python3-pexpect, python3-pil, python3-pytz, python3-certifi, python3-charset-normalizer, python3-idna, python3-chardet, python3-requests, python3-webencodings, python3-tinycss2
Impact: The packages ARE installed, but Python bytecode compilation fails. This means:

✅ Package files are on disk
✅ Code will work when imported
❌ Performance is slightly degraded (no .pyc cache)
❌ py3compile postinst hook fails (non-fatal in practice)
Suggested fix for runepkg: Ensure dpkg --get-selections and related queries work correctly in the postinst environment. You might need to:

Regenerate dpkg status after each package
Or bypass py3compile for problematic packages
Or run py3compile after all installations complete
2. NetworkManager Postinst Failure ⚠️ INFRASTRUCTURE ISSUE (WSL-related)
Code
chmod: cannot access '/var/lib/NetworkManager': No such file or directory
ERROR: Maintainer script postinst failed with status 1
Root cause: NetworkManager tries to set permissions on a directory that doesn't exist. This is expected on WSL because:

WSL doesn't run NetworkManager as a service
The directory structure may not be set up
WSL networking is handled differently
This is not a runepkg bug—it's a WSL limitation. The package installs, but the service setup fails (which is fine since you can't run it anyway on WSL).

Fix: You can suppress this with --force or by skipping NetworkManager on WSL.

Error: The following dependencies are not satisfied:
  - policykit-1-gnome

This is correct behavior from runepkg—it detected an unmet dependency and warned you.
