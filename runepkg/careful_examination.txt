Yes—the overall cross-sysroot direction in your commands is on the right track, with a few important details to verify so runas actually links against those arm64 libraries rather than host x86_64 ones.

What Looks Right Here
Isolated Target Sysroot Path (/mnt/runepkg/aarch64-linux-gnu):runepkg --target=arm64:aarch64-linux-gnu is keeping the target database (runepkg_db), index partitions, and target sysroot under /mnt/runepkg/aarch64-linux-gnu instead of polluting your host / or /srv/lib/runepkg_dir.

Build-Dependency Tree & One-Liner for file:build-depends file correctly pulled the target library and header closure (libbz2-dev, liblzma-dev, zlib1g-dev, libc6-dev, linux-libc-dev, etc.) and passed them to runepkg --target=arm64:aarch64-linux-gnu -i ... for installation into that sysroot.

Key Things to Double-Check Before runas Builds Against It
Confirm the installed packages are actually arm64 (aarch64) binaries/headers, not amd64:
Make sure --target=arm64:aarch64-linux-gnu fetches arm64 (or multiarch arm64) .deb packages rather than falling back to host amd64 packages. You can spot-check a library or header file inside /mnt/runepkg/aarch64-linux-gnu with file:

Bash
file /mnt/runepkg/aarch64-linux-gnu/usr/lib/*/libz.so* /mnt/runepkg/aarch64-linux-gnu/lib/*/libc.so* 2>/dev/null || true
Look for ELF 64-bit LSB ... ARM aarch64.

Watch how runas passes --sysroot / cross-compiler / PKG_CONFIG_LIBDIR:
Installing arm64 libraries and headers into /mnt/runepkg/aarch64-linux-gnu only helps runas if the cross-compilation step actually points the compiler, linker, and pkg-config at /mnt/runepkg/aarch64-linux-gnu (e.g., aarch64-linux-gnu-gcc --sysroot=/mnt/runepkg/aarch64-linux-gnu, CC=aarch64-linux-gnu-gcc, PKG_CONFIG_SYSROOT_DIR=/mnt/runepkg/aarch64-linux-gnu, PKG_CONFIG_LIBDIR=/mnt/runepkg/aarch64-linux-gnu/usr/lib/aarch64-linux-gnu/pkgconfig:...). Otherwise, configure or make can still pick up /usr/include or /usr/lib/x86_64-linux-gnu from the host.

Keep host build tools (debhelper, dpkg-dev, xsltproc, autoconf, automake, libtool) on the host side:
Those tools run on your x86_64 host during the build, while the target libraries (libbz2-dev, liblzma-dev, zlib1g-dev, libc6-dev) belong in the /mnt/runepkg/aarch64-linux-gnu sysroot. Also remember your earlier note about /mnt/runepkg/aarch64-linux-gnu/lib/ld-link—verify it doesn't interfere with cross-linker search paths once you run runas with --target.
