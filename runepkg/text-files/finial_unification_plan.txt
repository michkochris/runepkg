Implementation Plan: runepkg & runas Target Unification & Per-Profile Architecture
This plan specifies the technical implementation details for unifying target profiles, toolchain sysroot paths (target_sysroot), per-profile package state tracking (<sysroot>/srv/lib/runepkg_dir/runepkg_db), disposable profile management, predictive psychic_matrix.bin sysroot indexing, C89/C++17 boundary safety, and predictive FSM head/tail tracking across runepkg (psychic) and runas.
User Review Required & Design Invariants
Important
Self-Contained Target Config Provisioning (<sysroot>/etc/runepkg/): When a target sysroot /mnt/runepkg/<profile> is staged or initialized:
•
Native Config Provisioning: runepkg provisions <sysroot>/etc/runepkg/runepkgconfig and <sysroot>/etc/runepkg/config_registry.txt pre-configured for native operation (install_dir=/, runepkg_db=/srv/lib/runepkg_dir/runepkg_db).
•
Chroot & Boot Readiness: If /mnt/runepkg/<profile> is chrooted or booted on real hardware, runepkg running natively inside finds its own valid /etc/runepkg/runepkgconfig and runepkg_db in place.
•
Active State Entanglement: <sysroot>/etc/runepkg/active_target.conf is written with ACTIVE_TARGET=<profile> so native target tools recognize their sysroot identity.
Important
Single Authoritative DB Path Formula (runepkg_config_get_effective_db_dir): Host runepkg computes g_runepkg_db_dir using one single formula across all execution modes:
•
If <root> == / (Host Root): Returns /srv/lib/runepkg_dir/runepkg_db (tracks ONLY host packages installed directly to /).
•
If <root> != / (Alternate install_dir OR Target Profile target_sysroot): Returns <root>/srv/lib/runepkg_dir/runepkg_db (e.g. /mnt/runepkg/<profile>/srv/lib/runepkg_dir/runepkg_db or /srv/lib/runepkg_dir/install_dir/srv/lib/runepkg_dir/runepkg_db).
•
Unified Maintenance: One single path formula maintains database isolation for both alternate install locations and cross-target sysroots.
•
Self-Contained & Chroot Native: If <root> is chrooted or booted into, runepkg running natively inside finds its database at /srv/lib/runepkg_dir/runepkg_db.
•
Single-Step Teardown: Deleting /mnt/runepkg/<profile> via runepkg -r --remove-profile <profile> automatically deletes both the sysroot and its database in a single rm -rf step with zero host residue.
Important
Staged Execution Phases:
1.
Phase 1 (Pass One - Core Isolation): Unify TargetProfile struct, implement 4-tier target precedence, single effective DB path helper (runepkg_config_get_effective_db_dir), CLI --target=<profile> flag, safe teardown (remove-profile), and target /etc/runepkg/ config provisioning.
2.
Phase 2 (Debian-First runas): Bind runas matrix parsing to TargetProfile, update sysroot build paths to /mnt/runepkg/<profile>, wire Multi-Arch dependency filters, and preserve legacy runas build-toolchain intact.
3.
Phase 3 (psychic_matrix.bin & Prophecy): Implement psychic_matrix.bin binary serialization with "PSYC" header bounds checking, header/library-to-Debian prophecy mapping, and pre-flight sysroot probes.
4.
Phase 4 (FSM Head/Tail Tracking): Wire head/tail transaction state logging in runepkg_state.c.
Important
C89 Memory & Pointer Ownership Rule (const char *):
•
Managed Pointer Ownership: runepkg_config_get_effective_db_dir() returns a const char * pointer to managed memory (g_runepkg_db_dir), valid for the process lifetime. Callers do not free this pointer.
•
Buffer Filling Convention: Helpers that format path strings (e.g. runepkg_config_get_profile_paths(profile_name, out_sysroot, sysroot_sz, out_db_dir, db_sz)) write into caller-supplied stack buffers, completely eliminating heap allocation leaks in C89.
Important
Binary Format Bounds & Struct Safety (psychic_matrix.bin):
•
Binary Header Layout: Contains char magic[4] ("PSYC"), uint32_t version, uint32_t entry_count, and uint64_t total_bytes.
•
Bounds Validation: Readers verify magic == "PSYC", version == 1, and total_bytes == actual_file_size before parsing records. If truncated or invalid, psychic safely auto-regenerates the index by scanning the sysroot.
Important
Teardown Safety & Nonexistent Path Guardrail (remove-profile):
•
Nonexistent Path No-Op: runepkg -r --remove-profile <profile> checks runepkg_util_file_exists() first; if absent, returns success immediately (clean no-op).
•
realpath() Boundary Check: If present, resolves realpath(), verifies the canonical path starts strictly with /mnt/runepkg/, and verifies it is NOT /, /mnt, or /mnt/runepkg before executing recursive removal.
Important
Canonical Profile Name vs. deb_host_arch (arm64 vs. aarch64-linux-gnu): runepkg_psychic_parse_target_arch() populates both fields side-by-side in TargetProfile:
•
deb_host_arch (arm64): Used for Debian repository queries, stanza matching, and package qualifiers (:arm64).
•
triplet (aarch64-linux-gnu): Canonical profile identifier used for sysroot directory pathing (/mnt/runepkg/aarch64-linux-gnu), multi-arch header paths (/usr/include/aarch64-linux-gnu), library paths (/usr/lib/aarch64-linux-gnu), and dynamic linkers.
Important
C89 vs. C++17 Boundary & Atomic State Activation:
1.
Strict C89 Header Standard: All declarations in runepkg_config.h and runepkg_psychic.h remain strictly C89-compliant (/* */ comments, top-of-block variable declarations, wrapped in extern "C" when included by .cpp files).
2.
Atomic Profile Activation: runepkg_config_activate_profile() sets g_active_profile, g_target_sysroot, and g_runepkg_db_dir atomically in one entry point before any C++ runas module accesses target context.
Important
4-Tier Target Precedence Order: Target context resolution in runepkg_config.c strictly follows this 4-tier hierarchy:
1.
CLI Flag (--target=<profile>) — Highest precedence; overrides session and config for the invocation.
2.
Active Session State (active_target.conf) — Created/managed via switch <profile> and cleared via switch --reset.
3.
Config File Defaults (runepkgconfig) — Reads target_arch / target_sysroot if present.
4.
Host Mode (x86_64-linux-gnu, /) — Fallback when no target is specified anywhere. Invariance Rule: switch commands only write active_target.conf and NEVER modify runepkgconfig on disk.
