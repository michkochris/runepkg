DESIGN.md, the architecture naturally organizes around five foundational principles:Core Architectural Pillars for DESIGN.mdThe Dual-Engine Division of Labor (C89 Core vs. C++17 Forge):Why: Embedded systems, recovery media, and initramfs need a zero-dependency, small-footprint installer (~400–530 KB) that compiles on any legacy or modern toolchain without dynamic library baggage.How: ISO C90 compliance at the base layer handles local .deb operations and binary lookups, while modern C++ handles parallel networking, graph resolution, and cross-compilation orchestration.Binary-First Serialization ($O(1)$ over Flat Files):Why: Scanning monolithic text databases (like /var/lib/dpkg/status or uncompressed package lists) creates severe I/O and parsing bottlenecks on constrained systems.How: Using fixed-layout binary structures (pkginfo.bin, matrix_rules.bin, runepkg_autocomplete.bin) combined with prime-resizing FNV-1a hash buckets and mmap allows instant lookups with zero allocation overhead.Decoupling Logic from Data (The Matrix Engine):Why: Embedding package-specific build workarounds in C++ causes binary bloat, long recompilation cycles, and brittle maintenance.How: Treating the C++ engine as a generic state machine and moving package behaviors into declarative text rules (rules.d/*.txt) with an integrated JIT compilation step gives you both human-editable customization and binary execution speed.Hermetic, Destructible Toolchain Bootstrapping:Why: Cross-compiling for embedded targets (especially non-glibc runtimes like musl) often fails due to host environment leakage, header contamination, or wrong PT_INTERP dynamic linker paths.How: A strict 4-stage bootstrap (Binutils $\rightarrow$ Freestanding GCC Core $\rightarrow$ Sanitized Headers/Libc $\rightarrow$ Full GCC Runtime) into an isolated target prefix (/mnt/runepkg/<profile>/) ensures deterministic binaries that can be built and wiped cleanly.Pruned Dependency Graph Harvester:Why: Standard Debian source packages pull in massive dependency webs (documentation suites, test frameworks, language runtimes) that are irrelevant or actively harmful on embedded targets.How: The resolver
