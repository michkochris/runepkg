================================================================================
THEORY: THE PSYCHIC DEBIAN PACKAGE MANAGER (runepkg_psychic)
================================================================================

1. Core Premise
----------------
Traditional package managers treat every operating system and package repository as an unknown black box, relying on reactive error handling, generic heuristics, and trial-and-error resolution.

Because **runepkg** is engineered exclusively and unconditionally for the **Debian ecosystem**, it does not need to guess. The Debian universe is deterministic: its FHS hierarchy, Multi-Arch directory standards, dynamic linker naming conventions (`ld-linux-*`), virtual package topologies, and maintainer script lifecycles are immutable invariants.

By leveraging this certainty, **runepkg** becomes "psychic"—anticipating missing structural scaffolding, resolving virtual package loops, and projecting multi-arch target sysroots *before* extraction failures or dependency dead-ends occur.

2. Dual-Root Configuration Architecture (The Foundation)
------------------------------------------------------
To make multi-arch staging rock-solid, `runepkg` introduces a second install root variable in `runepkgconfig`:
- **`install_dir`**: The primary host / default staging root.
- **`target_install_dir` (or `sysroot_dir`)**: The dedicated cross-arch embedded target sysroot.

This completely separates host operations from target cross-staging, ensuring `runepkg_psychic` knows precisely where to anchor dynamic linkers and multi-arch library directories.

3. Hermetic Isolation & Dpkg/Apt Interoperability
-------------------------------------------------
A critical challenge in alternate root staging is avoiding host state contamination. By decoupling `target_install_dir` from the host:
- Host/native alternate root operations (`install_dir`) can optionally participate in **dpkg Quantum Entanglement** (`dpkg_host=auto`) when architectures match.
- Cross-architecture embedded target sysroots (`target_install_dir`) operate under **strict hermetic isolation**, bypassing host `dpkg`/`apt` entanglement entirely. This prevents cross-contamination of host package registries with foreign architecture stanzas (e.g., staging `arm64` on an `amd64` host).
