Implementation Plan: runepkg & runas Target Unification & Per-Profile Architecture
This plan specifies the technical implementation details for unifying target profiles, toolchain sysroot paths (target_sysroot), per-profile package state tracking (runepkg_db/<profile>), disposable profile management, predictive psychic_matrix.bin sysroot indexing, C89/C++17 boundary safety, and predictive FSM head/tail tracking across runepkg (psychic) and runas.
User Review Required & Design Invariants
Important
C89 Memory & Pointer Ownership Rule (const char *):
•
Managed Pointer Ownership: runepkg_config_get_effective_db_dir() returns a const char * pointer to managed memory (g_runepkg_db_dir), valid for the process lifetime. Callers do not free this pointer.
•
Buffer Filling Convention: Helpers that format path strings (e.g. runepkg_config_get_profile_paths(profile_name, out_sysroot, sysroot_sz, out_db_dir, db_sz)) write into caller-supplied stack buffers, completely eliminating heap allocation leaks in C89.
Important
Single Authoritative DB Path Function (runepkg_config_get_effective_db_dir): A single function runepkg_config_get_effective_db_dir() calculates and sets the active database directory:
•
Host Root (install_dir = /): Returns /srv/lib/runepkg_dir/runepkg_db (tracks ONLY host packages installed directly to /).
•
Alternate install_dir or Target Sysroot (target_sysroot): Returns <install_dir_or_sysroot>/srv/lib/runepkg_dir/runepkg_db.
•
Zero Host Fallback: Completely eliminates competing DB paths or host fallback during target profile queries.
Important
Binary Format Bounds & Struct Safety (psychic_matrix.bin):
•
Binary Header Layout: Contains char magic[4] ("PSYC"), uint32_t version, uint32_t entry_count, and uint64_t total_bytes.
•
Bounds Validation: Readers verify magic == "PSYC", version == 1, and total_bytes == actual_file_size before parsing records. If truncated or invalid, psychic safely auto-regenerates the index by scanning the sysroot.
Important
Teardown Safety & Nonexistent Path Guardrail (remove-profile):
•
Nonexistent Path No-Op: runepkg -r --remove-profile <profile> checks runepkg_util_file_exists() first; if absent, returns success immediately (clean no-op).
•
realpath() Boundary Check: If present, resolves realpath(), verifies the canonical path starts strictly with /mnt/runepkg/, and verifies it is NOT /, /mnt, or /mnt/runepkg before executing recursive removal.
Important
Canonical Profile Name vs. deb_host_arch (arm64 vs. aarch64-linux-gnu): runepkg_psychic_parse_target_arch() populates both fields side-by-side in TargetProfile:
•
deb_host_arch (arm64): Used for Debian repository queries, stanza matching, and package qualifiers (:arm64).
•
triplet (aarch64-linux-gnu): Canonical profile identifier used for sysroot directory pathing (/mnt/runepkg/aarch64-linux-gnu), multi-arch header paths (/usr/include/aarch64-linux-gnu), library paths (/usr/lib/aarch64-linux-gnu), and dynamic linkers.
Important
C89 vs. C++17 Boundary & Atomic State Activation:
1.
Strict C89 Header Standard: All declarations in runepkg_config.h and runepkg_psychic.h remain strictly C89-compliant (/* */ comments, top-of-block variable declarations, wrapped in extern "C" when included by .cpp files).
2.
Atomic Profile Activation: runepkg_config_activate_profile() sets g_active_profile, g_target_sysroot, and g_runepkg_db_dir atomically in one entry point before any C++ runas module accesses target context.
Important
4-Tier Target Precedence Order: Target context resolution in runepkg_config.c strictly follows this 4-tier hierarchy:
1.
CLI Flag (--target=<profile>) — Highest precedence; overrides session and config for the invocation.
2.
Active Session State (active_target.conf) — Created/managed via switch <profile> and cleared via switch --reset.
3.
Config File Defaults (runepkgconfig) — Reads target_arch / target_sysroot if present.
4.
Host Mode (x86_64-linux-gnu, /) — Fallback when no target is specified anywhere. Invariance Rule: switch commands only write active_target.conf and NEVER modify runepkgconfig on disk.
