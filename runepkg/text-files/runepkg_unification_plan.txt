Implementation Plan: runepkg & runas Target Unification & Per-Profile Architecture
This plan specifies the technical implementation details for unifying target profiles, toolchain sysroot paths (target_sysroot), per-profile package state tracking (runepkg_db/<profile>), disposable profile management, predictive psychic_matrix.bin sysroot indexing, C89/C++17 boundary safety, and predictive FSM head/tail tracking across runepkg (psychic) and runas.
User Review Required & Design Invariants
Important
Canonical Profile Name vs. deb_host_arch (arm64 vs. aarch64-linux-gnu): runepkg_psychic_parse_target_arch() populates both fields side-by-side in TargetProfile:
•
deb_host_arch (arm64): Used for Debian repository queries, stanza matching, and package qualifiers (:arm64).
•
triplet (aarch64-linux-gnu): Canonical profile identifier used for sysroot directory pathing (/mnt/runepkg/aarch64-linux-gnu), multi-arch header paths (/usr/include/aarch64-linux-gnu), library paths (/usr/lib/aarch64-linux-gnu), and dynamic linkers.
•
runepkg_config_get_profile_paths() strictly uses canonical triplet for path generation and never confuses deb_host_arch with triplet.
Important
Order of Operations & Teardown Safety:
1.
Write Ordering for psychic_matrix.bin: During package installation/removal in a target sysroot (runepkg --target=... -i <pkg>), psychic_matrix.bin is updated/regenerated AFTER package extraction and runepkg_psychic_anchor_dynamic_linker() complete so the binary index reflects the final staged state (including dynamic linker symlinks).
2.
Teardown Safety Guardrail: runepkg -r --remove-profile <profile> strictly validates the resolved sysroot path (verifying it is non-empty, contains /mnt/runepkg/, and is NOT /, /mnt, or /mnt/runepkg) before executing recursive removal to prevent accidental host system deletion.
Important
C89 vs. C++17 Boundary & Atomic State Activation:
1.
Strict C89 Header Standard: All declarations in runepkg_config.h and runepkg_psychic.h remain strictly C89-compliant (/* */ comments, top-of-block variable declarations, wrapped in extern "C" when included by .cpp files).
2.
Atomic Profile Activation: runepkg_config_activate_profile() sets g_active_profile, g_target_sysroot, and g_runepkg_db_dir atomically in one entry point before any C++ runas module (runepkg_building.cpp, runepkg_matrix.cpp) accesses target context.
Important
Strict Database Tracking Rule: Host Root vs. Alternate install_dir:
•
Host Root Installation (install_dir = /): The host root database at /srv/lib/runepkg_dir/runepkg_db ONLY tracks host-specific packages installed directly to / root.
•
Alternate install_dir (anything other than / root): When install_dir is set to any directory other than / (e.g. /srv/lib/runepkg_dir/install_dir or custom directory), runepkg abandons tracking in the host root database.
•
Self-Contained Database Insertion: Instead, runepkg inserts a self-contained database directly inside that install location at: <install_dir>/srv/lib/runepkg_dir/runepkg_db
•
Target Profile Sysroots: Target profiles insert their database inside: <target_sysroot>/srv/lib/runepkg_dir/runepkg_db (e.g. /mnt/runepkg/<profile>/srv/lib/runepkg_dir/runepkg_db).
Important
4-Tier Target Precedence Order: Target context resolution in runepkg_config.c strictly follows this 4-tier hierarchy:
1.
CLI Flag (--target=<profile>) — Highest precedence; overrides session and config for the invocation.
2.
Active Session State (active_target.conf) — Created/managed via switch <profile> and cleared via switch --reset.
3.
Config File Defaults (runepkgconfig) — Reads target_arch / target_sysroot if present.
4.
Host Mode (x86_64-linux-gnu, /) — Fallback when no target is specified anywhere. Invariance Rule: switch commands only write active_target.conf and NEVER modify runepkgconfig on disk.
Important
psychic_matrix.bin Sysroot Inventory vs. Prophecy Mapping:
•
Sysroot Inventory (psychic_matrix.bin): O(1) binary index of what is currently staged inside the sysroot (/lib, /usr/lib, /usr/lib/<triplet>, /usr/include, /usr/include/<triplet>).
•
Header/Library-to-Debian Prophecy Mapping: Cross-references binary repo indices (repo_index.bin / harvested Contents-<arch> metadata) to resolve missing headers (e.g. <zlib.h>) or missing link flags (e.g. -lz) to candidate Debian .deb packages (e.g. zlib1g-dev:arm64).
Important
Preserving runas build-toolchain & UsrMerge Dynamic Linkers:
•
Legacy Preservation: Raw CLFS cross-toolchain build code (runas build-toolchain) is preserved intact and isolated for specialized edge cases (uClibc, bare metal) without altering its code path.
•
Standard Debian Build Flow: Standard runas --target=<profile> build <pkg> defaults to the staged sysroot (/mnt/runepkg/<profile>) + standard Debian build flow.
•
UsrMerge Dynamic Linkers: runepkg_psychic_anchor_dynamic_linker() checks and anchors dynamic linkers at both /lib/ld-linux-aarch64.so.1 and /lib/aarch64-linux-gnu/ld-linux-aarch64.so.1 pointing into usr/lib/aarch64-linux-gnu/.

•
Implement 4-tier target resolution order in runepkg_config_load().

Implement atomic target activation in runepkg_config_activate_profile().
•
Enforce strict database path assignment rule:

◦
If operating under a target profile (target_sysroot): g_runepkg_db_dir = <target_sysroot>/srv/lib/runepkg_dir/runepkg_db.
•
Ensure runepkg_config_save_active_state() only updates active_target.conf without touching runepkgconfig.
