1. Binary-First Storage Model (Zero-Copy Efficiency)
The code abandons text-file parsing entirely—the core problem of traditional dpkg. Instead:

C
// runepkg_storage.c: Hierarchical package-version storage

Why brilliant:

O(1) lookup via FNV-1a hash: hash_function(name) % prime_table_size (runepkg_hash.c:55-68)
Prime-sized buckets: Guarantees collision distribution without power-of-2 clustering
Zero-allocation memory-mapping: runepkg_autocomplete.bin serves 100k+ packages without touching memory allocator
Embedded-first: Works on initramfs with zero dynamic heap pressure

4. Dynamic Hash Table with Prime-Sized Resizing
C
// runepkg_hash.c:42-50 - Finds next prime to avoid clustering
static size_t find_next_prime(size_t num) {
    if (num <= 2) return 2;
    if (num % 2 == 0) num++;
    while (!is_prime(num)) {
        num += 2;
    }
    return num;
}
