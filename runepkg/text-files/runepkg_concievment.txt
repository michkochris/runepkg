PROJECT DIRECTIVE: RUNEPKG NASA-GRADE ARCHITECTURAL REFACTORING
================================================================================
1. CORE IDENTITY & POSITIONING
- runepkg is NOT a competitor to dpkg, apt, pacman, or busybox package utilities. 
  Those tools solve high-level OS distribution problems with dynamic runtimes, 
  heavy scripting layers, and legacy baggage.
- runepkg is a foundational, ultra-low-level computer science project engineered 
  to NASA-grade software reliability standards: deterministic execution, strict 
  memory safety, zero hidden allocations, and total predictability down to the metal.
2. ENGINEERING PRINCIPLES (C89 / C90 BASELINE)
- Language: Pure, strict C89/90. No compiler-specific extensions or bloated wrappers.
- Zero Garbage: No temporary files, no auxiliary junk files, no redundant abstractions. 
  Every operation must be direct, lightning-fast, and auditable.
- Determinism: Given identical source inputs and build-depends, execution paths 
  and outcomes must be 100% reproducible and deterministic.
- Fault Isolation: Defensive error handling at every boundary. No unhandled null pointers, 
  no silent truncation, and rigid validation of all source manifests and build parameters.
3. ARCHITECTURAL PURPOSE
- To serve as a high-integrity source-based package management kernel for specialized 
  Linux environments (such as a source-based Debian derivative).
- To download source trees, verify source-depends and source-build-depends, and orchestrate 
  build processes with the mechanical precision of an aerospace control system.
4. MANDATE FOR AI COLLABORATORS
- When generating, reviewing, or refactoring code for runepkg, evaluate every function 
  through the lens of mission-critical reliability, strict bounds checking, and absolute 
  adherence to pure C89 principles. Reject bloat, reject temporary workarounds, and 
  maintain the unwavering standard of a Jedi Linux Source Master.
