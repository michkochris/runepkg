Diagnostic Analysis: Root Cause & Prevention of Host Environment Corruption
1. Executive Summary
During the execution of runepkg upgrade with the host installation directory configured to system root (install_dir=/), runepkg processed and executed a full system upgrade against the live Kali Linux WSL environment. This resulted in core system binaries and interpreters (/bin/bash, /bin/sh, and core dynamic linkers/libc) being overwritten or unlinked, leading to the terminal WSL error:execvpe(/bin/bash) failed: No such file or directory

2. Root Cause Analysis
A. Live Host Upgrade Execution (runepkg upgrade against /)
Mechanism: runepkg update fetched the latest Kali Rolling repository indexes. runepkg upgrade identified 241 upgradable packages and planned a full system replacement.

The Danger: Unlike a dedicated package manager (apt / dpkg) which maintains complex transaction ordering, pre/post-install safety hooks, and multi-arch fallback protections for running host environments, runepkg's generic installation pipeline unzipped and overwrote binaries and libraries directly into the target prefix.

Dynamic Linker & libc Mismatch: When libc6, bash, or dynamic linkers (ld-linux-x86-64.so.2) are upgraded out-of-order on a live running Linux system, all subsequent process spawns (fork/exec) fail instantly because the new libraries require symbols or paths that do not match the running kernel/process memory space.

B. Host Entanglement (install_dir=/ + dpkg_host=auto)
Allowing install_dir to default to / without immutable guardrails invites accidental host pollution. A package manager engineered for isolated or target-sysroot forging should never perform destructive bulk upgrades (like upgrade or bulk -i) on the live host system root without explicit hazard overrides.

3. Permanent Preventative Guardrails (Implementation Blueprint)
To ensure this never happens again, runepkg requires the following architectural defenses:

Host Root Hazard Lock (install_dir == /):

runepkg upgrade and bulk package installations must hard-abort with a safety error if install_dir == "/" unless an explicit override flag (--danger-live-host-override) is supplied by the user.

Protected System Package Blacklist:

Maintain a hardcoded defensive blacklist of critical system packages (libc6, bash, dash, dpkg, systemd, linux-base, coreutils) that runepkg is strictly forbidden from upgrading or replacing when operating on a live host root.

Default Sandbox Enforced:

Default install_dir in runepkgconfig must point to a safe user-space container directory (/srv/lib/runepkg_dir) rather than /, ensuring all experiments remain fully sandboxed away from the host OS.
